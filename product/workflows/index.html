One engine, every kind of ticketOne engine, every kind of ticket

Label a ticket where it already lives and the label picks the workflow: a feature, a CI fix, a review, a build check, a spec. Each runs on the same engine in its own disposable sandbox, and the runs screen is the queue.
Tickets from where they live
GitHub, GitLab, Bitbucket Cloud, Linear, Jira and Sentry, or a webhook.
Intake asks first
A thin ticket gets the questions it is missing asked on the ticket itself, before anything is spent.
One sandbox per run
Each run gets its own container, on the sandbox image the project sets, discarded with the run.

A real run

One ticket, start to merge, with every step and every cost on the record.
